# K-STE

**ASD-STE100의 명확한 기술 문장 작성 원칙을 한국어 AI 의사소통에 맞게 응용한 스킬**입니다. 사용자의 작업 지시뿐 아니라 AI가 사용자에게 제공하는 기술·학습·오류 설명에도 **필요한 영역만** 선택적으로 적용합니다.

일반 대화나 모든 프롬프트·답변에 규칙을 강제하지 않습니다. 사용자가 입력 지시, AI 출력 설명, 양방향 가운데 원하는 방향과 영역을 선택할 수 있습니다.

## 설계 배경: ASD-STE100

[ASD-STE100](https://www.asd-ste100.org/)은 항공우주·방위산업 분야의 기술 문서를 명확하게 작성하기 위한 간소화 기술 영어 표준입니다. K-STE는 여기서 강조하는 **일관된 용어, 명확한 작업 지시, 모호함의 최소화**라는 접근을 참고하여 한국어 AI 입력 지시와 출력 설명에 맞게 재구성했습니다.

다만 영어 문장 규칙을 그대로 번역한 것은 아닙니다. 한국어에서 자주 생략되는 주어와 목적어, 불명확한 지시어, 작업 조건·예외의 적용 범위뿐 아니라 AI 설명의 논리적 연결, 근거와 불확실성 구분을 중점적으로 다룹니다. 또한 모든 문장에 규칙을 강제하지 않고 **사용자가 선택한 영역에만 적용**합니다.

**K-STE는 ASD-STE100의 공식 한국어판이나 인증·준수 검사 도구가 아닙니다.** 공식 표준의 승인 어휘 사전을 포함하거나 표준 준수를 보증하지 않습니다.

## 세 가지 사용 모드

| 모드 | 적용 방향 | 사용 목적 |
|---|---|---|
| **입력 명확화** | 사용자 → AI | 요구사항과 변경 금지 조건처럼 선택한 지시문만 정리 |
| **출력 명확화** | AI → 사용자 | 기술·학습·오류 설명, 요약 중 요청한 유형만 명확하게 설명 |
| **양방향 명확화** | 양쪽 모두 | 사용자가 지정한 입력·출력 영역만 각각 처리 |

**예:** "프롬프트의 제약 조건과 AI 답변의 오류 설명에만 K-STE를 적용해 줘."

출력 모드는 **AI가 설명을 생성할 때**도 적용할 수 있습니다. 모든 설명을 짧게 축약하거나 불필요한 규칙을 강제하지 않습니다. 특히 학습 설명의 논리, 수식과 예외 조건을 보존합니다.

## 특징

- **기본 비활성:** 사용자가 명확화를 요청하지 않은 경우 원문 유지
- **부분 적용:** 요청된 영역만 분석 및 수정
- **의미 보존:** 사실, 수치, 필수/권장/선택 강도, 조건, 예외와 금지 사항 보존
- **가정 금지:** 누락된 값을 임의로 채우지 않고 확인 필요 항목으로 표시
- **진단과 재작성 분리:** 자동 검사는 경고만 표시하며 임의 수정하지 않음
- **한국어 우선:** 지시 대상, 생략된 주어, 모호한 표현과 설명의 논리적 흐름에 초점
- **설명 유형별 규칙:** 기술 설명은 조건·용어, 학습 설명은 논리·예시, 오류 설명은 관찰·추정 구분

## 사용 예시

```text
다음 개발 요청에서 '작업 요구사항'과 '변경 금지 조건'만 K-STE로 명확하게 고쳐줘.
다른 설명은 수정하지 마.
```

```text
이 문서의 결과물 형식만 K-STE로 점검해줘. 재작성하지 말고 위험한 표현만 알려줘.
```

```text
UI 설계는 자유롭게 두고, DB 변경 조건만 명확히 적어줘.
```

```text
이번 답변의 수학 개념 설명에만 K-STE를 적용해 줘. 논리와 수식은 유지해 줘.
```

```text
이 오류의 원인을 설명할 때 K-STE를 적용해 줘. 확인된 사실과 가능한 원인을 구분해 줘.
```

## 사용 방식

1. AI 스킬을 지원하는 환경에 이 저장소의 `SKILL.md`를 등록합니다.
2. `K-STE`와 적용 방향(입력·출력·양방향), 영역을 지정합니다.
3. AI는 요청한 영역만 명확화합니다. 출력 모드에서는 해당 설명을 명확한 방식으로 직접 작성할 수도 있습니다.

### 검사기

Python 3.10 이상, 외부 패키지 없음.

```bash
python scripts/kste_lint.py instructions.md --scope requirements,constraints
python scripts/kste_lint.py instructions.md --scope output --format json
python scripts/kste_lint.py response.md --direction output --scope technical,learning
python scripts/kste_lint.py conversation.md --direction both --scope input:constraints,output:error
python scripts/kste_lint.py instructions.md --all
python -m unittest discover -s tests -v
```

영역 식별은 Markdown 제목 또는 명시적 구간 표식을 사용합니다. 입력의 `--scope output`은 **결과물 형식**을 뜻하며, AI 출력 설명은 `--direction output`으로 선택합니다.

```markdown
## 작업 요구사항
게시글의 첨부파일을 슬라이드 위에 표시한다.

## 제약 조건
기존 게시글 데이터는 삭제하지 않는다.
```

제목이 없는 문서에서는 다음 표식을 사용할 수 있습니다.

```text
<!-- kste:start scope=requirements -->
이거 적절하게 수정해줘.
<!-- kste:end -->
```

기본값은 **입력 지시 영역만 검사**하며, 전체 문서 검사 금지입니다. 영역이 없으면 검사기에서 오류 코드 2로 중단합니다. `--all`은 한 방향을 명시적으로 전체 검사할 때만 사용합니다. 양방향은 반드시 `input:영역,output:영역`을 지정해야 합니다.

출력 영역 제목은 `## 기술 설명`, `## 학습 설명`, `## 오류 설명`, `## 요약`입니다. 출력 표식은 `<!-- kste:start scope=technical direction=output -->`처럼 사용합니다.

## 파일

- `SKILL.md`: 선택 적용 정책과 재작성 절차
- `references/ko-rules.md`: 한국어 입력 지시 명확화 규칙
- `references/response-rules.md`: AI 출력 설명의 유형별 명확화 규칙
- `examples/usage.md`: 적용 예시
- `scripts/kste_lint.py`: 선택 영역 검사기
- `tests/`: 동작 검증

## 유의 사항

이 스킬은 프롬프트와 AI 설명의 모호함을 줄이는 보조 도구입니다. AI의 성능 향상이나 결과의 정확성을 보증하지 않습니다. 검사기는 표면적인 신호만 찾으며, 의미 일치 여부는 사람이 확인해야 합니다.
