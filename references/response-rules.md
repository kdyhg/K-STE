# AI 출력 설명 명확화 규칙

K-STE의 출력 모드는 **AI가 사용자에게 설명을 생성하거나 이미 생성한 설명을 고쳐 쓸 때** 사용한다. 모든 응답을 자동으로 간소화하는 기능은 아니다. 사용자가 지정한 유형·영역에만 적용한다.

## 기술 설명

- 무엇에 관한 설명인지 먼저 밝힌다.
- 대상/용어/입력/출력/제약을 구분한다.
- 작업 설명과 사실 설명을 혼동하지 않는다.
- 설명에 코드, 옵션, 명령어가 있으면 원형을 유지한다.
- 잘못된 성능이나 호환성 주장을 덧붙이지 않는다.

## 학습·수업 설명

- 학습자 수준에 맞는 용어를 사용하되 수학적 정확성을 유지한다.
- 전제, 추론, 결론이 어떻게 연결되는지 설명한다.
- 공식의 적용 조건과 예외를 빠뜨리지 않는다.
- 예시를 간단하게 쓰더라도 일반 정리의 증명으로 둔갑시키지 않는다.
- 수식·정의·증명은 별도의 타당성 검토가 필요하다.

## 오류 원인 설명

- **관찰:** 확인된 오류 메시지·증상·로그
- **가능한 원인:** 관찰로부터 추정한 가설
- **확인 방법:** 원인을 구분할 검증 방법
- **조치:** 원인이 맞을 때 적용할 해결책

관찰하지 않은 원인을 단정하지 않는다. 조치가 위험하거나 데이터를 삭제할 수 있다면 전제와 영향 범위를 설명한다.

## 요약

- 질문에 대한 결론을 명확히 보여준다.
- 조건, 예외, 불확실성과 중요한 수치를 남긴다.
- 내용을 더 짧게 만드는 과정에서 원문 의미를 바꾸지 않는다.

## 출력 예

**일반 표현**

> 오류가 나는 건 서버가 문제라서 그래요. 무조건 다시 설치하면 됩니다.

**K-STE 적용**

> 현재 오류 메시지만으로 원인을 확정할 수 없습니다. 서버 연결 문제일 가능성이 있습니다. 먼저 서버 응답과 연결 상태를 확인해 주세요. 재설치는 원인이 확인된 뒤 필요할 때 검토하세요.

이 예시는 실제 오류를 진단한 결과가 아니라 문장 표현 방식의 비교다.

## 출력 명확화 점검 질문

1. 설명 대상과 결론이 명확한가?
2. 설명에 없는 사실이나 근거를 추가하지 않았는가?
3. 확인된 사실과 가능성을 구별했는가?
4. 학습 설명에서 논리 단계와 적용 조건을 보존했는가?
5. 지정하지 않은 영역이나 일반 대화를 변경하지 않았는가?

## 자동 검사기의 한계

`scripts/kste_lint.py`는 지시어, 강한 단정, 중복 가능성 표현, 긴 문장만 일부 경고한다. 표현이 발견되었다고 잘못된 문장이라는 뜻은 아니다. 예를 들어 수학적으로 참인 "항상"은 바꾸지 않아야 한다. 검사의 경고는 **사람 또는 AI가 맥락을 다시 확인하라는 신호**일 뿐이다.
