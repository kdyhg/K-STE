# 한국어 작업 지시 명확화 규칙

## 적용의 우선순위

1. **적용 범위 보호:** 요청받지 않은 부분은 절대 수정하지 않는다.
2. **의미 보존:** 수치, 대상, 조건, 예외, 강도, 순서, 부정문, 기존 데이터 보존 요구를 그대로 유지한다.
3. **누락 추정 금지:** 확인할 수 없는 값은 새로 만들지 않는다.
4. **국소적 가독성 개선:** 필요한 표현만 고친다.

## 주요 검사 관점

| 검사 관점 | 위험 예 | 권장 처리 |
|---|---|---|
| 지시어 | 이거 수정해 줘 | 원문에 명확한 대상이 있으면 그 명칭 사용; 없으면 확인 요청 |
| 판단 기준 | 예쁘게 개선해 줘 | 디자인 기준이 없으면 제안과 필수 조건을 분리 |
| 대상 생략 | 완료되면 올려 | 무엇을 어디에 올리는지 원문에서 확인 |
| 복합 행동 | 확인하고 수정하고 배포해 | 확인 → 수정 → 배포 순서로 분리 |
| 조건 범위 | 로그인한 경우 수정 및 조회 | 조건이 수정과 조회 모두에 걸리는지 확인 |
| 부정의 범위 | 기존 데이터는 삭제하지 마 | 삭제 금지 대상을 생략하지 않음 |
| 용어 혼합 | 게시물/게시글/글 | 동일 대상임이 확실할 때만 통일 |
| 강도 변화 | 가능하면 수정해 → 반드시 수정해 | 강도 변화 금지 |
| 충돌 | 아무것도 바꾸지 말고 UI 수정 | 충돌 표시 후 해석을 확인 |
| 검증 가능성 | 잘 작동하게 | 증거·완료 조건이 주어졌는지 확인 |

## 짧은 지시보다 안전한 지시

좋은 결과는 단어 수 최소화가 아니라 해석 차이 감소다. 문장을 나눈 뒤에도 명령어의 논리 연산이 바뀌지 않도록 한다.

원문: `로그인한 관리자만 삭제할 수 있다.`

잘못된 변형: `로그인한다. 관리자가 삭제한다.`

올바른 변형: `삭제 기능은 로그인한 관리자에게만 허용한다.`

원문: `기존 게시글은 건드리지 않고 새 링크 기능을 추가한다.`

잘못된 변형: `링크 기능을 추가한다.`

올바른 변형: `새 링크 기능을 추가한다. 기존 게시글 데이터는 변경하지 않는다.`

## 진단과 수정의 차이

자동 검사 결과는 **편집 지시가 아닌 검토 신호**다. 대화 맥락상 `이거`가 분명한 경우, 실제 수정에서 무조건 바꾸지 않는다.

아래 표현을 단순히 금칙어로 취급하지 않는다.

- `가능하면`: 요청의 강도를 설명할 수 있다.
- `적절히`: 의도적으로 구현자에게 재량을 남긴 것일 수 있다.
- `기존 기능 유지`: 맥락에 따라 매우 구체적일 수 있다.

## 부분 적용 예

```markdown
# 요청
이 기능을 더 편리하게 만들어 줘.

## 작업 요구사항
첨부파일을 슬라이드 위에 표시해 줘.

## 제약 조건
기존 게시글은 삭제하지 마.

## 배경 설명
현재 페이지가 조금 복잡해 보여.
```

사용자가 `requirements,constraints`만 지정했다면 두 영역만 수정한다. 제목, 요청, 배경 설명은 그대로 둔다.

## 스킬 호출 시 확인 항목

- 사용자가 지시문 개선을 요청했는가?
- 어느 영역이 허용되었는가?
- 수정 전과 후에 수치·권한·금지·예외 조건이 모두 남는가?
- 새로 만든 조건이 없는가?
- 수정 바깥 영역이 동일한가?
